# v1.0.0 Benchmark Report

Release: `v1.0.0`

Live dashboard: https://sc-audit-benchmark.vercel.app/

## Executive Summary

The v1.0.0 benchmark tested three open-weight LLM scanner philosophies across
15 generated Solidity contracts and 8 SWC vulnerability classes. Qwen3-Coder
480B produced the strongest result: highest detection, highest quality, and the
best cost-adjusted score.

The most important finding is practical: code-specialized models can outperform
pure reasoning models on Solidity vulnerability detection while also being
cheaper to run.

## Results

| Model | Philosophy | Detection | Quality | Cost (15 scans) | Cost-adjusted |
|---|---|---:|---:|---:|---:|
| Qwen3-Coder 480B | Code specialist | 71.4% | 57.5 | $0.0034 | 17,041.6 |
| MiniMax M2.7 | Code + reasoning hybrid | 64.3% | 44.6 | $0.0237 | 1,882.4 |
| Step-3.5-Flash | Pure reasoning sparse MoE | 18.2% | 18.2 | $0.0357 | 508.8 |

## Interpretation

Qwen3-Coder 480B won both quality and value. It detected 71.4% of evaluated
scenarios and was materially cheaper than the other tested scanner models based
on commercial list-price token usage.

MiniMax M2.7 was competitive on detection but weaker on quality and
cost-adjusted score. Step-3.5-Flash lagged across detection, quality, and value.

## Audit-Firm Implications

- Model selection should be measured against vulnerability-specific workloads,
  not generic reasoning benchmarks.
- Cost matters because audit workflows can require repeated scans across many
  contracts and revisions.
- A benchmark that regenerates contracts is more useful for ongoing regression
  checks than a one-time fixed test set.
- LLM scanners should still be paired with human review and static analysis,
  especially for ordering-dependent and protocol-level bugs.

## Known Blind Spot

The tested lineup did not reliably catch transaction-order dependence
(`SWC-114`). This is important because front-running and ordering issues often
require protocol context, adversarial scenario modeling, and human audit
judgment.

## Reproduction

Run:

```bash
./run.sh --prepare-only
source .venv/bin/activate
python src/main.py
```

Primary output:

```bash
output/leaderboard.json
```

The benchmark is self-renewing, so newly generated contracts can shift exact
percentages. The checked-in output files preserve this v1.0.0 snapshot.
